## 2026-10-15 CPU 后端增量

用户追加分别创建 CPU/GPU，类型和规格固定、不互转。先将 CPU 接入现有授权、幂等及持久 dispatch，再复用 Res Notebook/PVC/启停/删除与 SG 终端；CPU 不构造 GPU plan/charges、不依赖 Acc。沿用 [CPU 合同](../specs/instance-mvp.md#cpu-增量合同)，不另建实例或账本框架。

退出条件：真实 Gov API → CPU Notebook → SG 写文件 → 两轮启停保盘 → 删除计算与专属卷，提供前端可用接口、镜像/preset 与启动恢复方法；保留旧 GPU 定向回归，GPU 实机缺设备时单独标记。前端代码由专人接手。

## 12. 工作包：尽早跑通真实链路

沿用 MVP-01～05 编号，以下内容替代旧任务包，**将最小 SG 接线和真实删除退额前移到 MVP-03 的首个切片**，不等所有列表页面完成才联调。

### MVP-01：冻结最小合同与实验配置

| 子任务 | 产物与退出条件 |
|---|---|
| 01.1 | 记录 Res／Gov／Acc／SG 实际版本、Proto 消费版本及可复用入口；不把计划当代码 |
| 01.2 | 固定可信 namespace 优先、缺省前缀＋UUID、首次保存后不变的合同与测试样例 |
| 01.3 | 准备一个实验租户环境、普通 SA、固定存储配置，复用现有网络；不建设统一映射服务 |
| 01.4 | 平台发布一份简短镜像约定和可用测试镜像，确定实际 shell／UID/GID |
| 01.5 | 验证实际 Notebook 启停、字段传递、PVC 重挂和最终回收；先验证共享规格，再补整卡 |

这里只固定正在使用的部署组合，不展开所有版本、存储和网络矩阵。

### MVP-02：Gov／Acc 最小公共接线

| 子任务 | 产物与退出条件 |
|---|---|
| 02.1 | Res owner 的固定 binding、服务身份、配额 code、退款身份及 Acc 关联范围登记 |
| 02.2 | 当前授权后先查原公开请求幂等；新请求才解析、占额、持久投递 |
| 02.3 | 公共退额和使用结束派生按 owner 申报语义调整，不查询 Kubernetes |
| 02.4 | 正式原 plan／charges／ACK 接线；同键不重复扣额，错 owner 或超额归还被拒绝 |
| 02.5 | 测试合法 owner 在无 DELETE／仍有占用记录时可归还，Acc 不清空实际占用；旧消费者回归 |

不增加通用策略引擎、自动跨服务补偿或另一套退款 RPC。

### MVP-03：首个真实可用切片

| 子任务 | 产物与退出条件 |
|---|---|
| 03.1 | 最小实例、操作、持久工作和 PVC 记录；接收真实 Gov 命令并返回持久 ACK |
| 03.2 | 解析保存 Namespace，复用 Image，创建工作盘与 Notebook；共享 GPU 实际运行 |
| 03.3 | 前移最小 SG 目标接线，用现有终端组件或实际协议客户端进入容器执行命令 |
| 03.4 | 删除计算和专属盘，Res 生成通知，Gov 原账归还，Acc 接受结束同步 |
| 03.5 | 连成 `Gov → Res → Notebook → SG → 删除／退额`，记录真实结果 |

**这个切片即使还没有完整管理页面，也必须是实际服务路径。** 不以手工创建 Pod、直接改数据库或测试注入完成通知代替它。基础授权、对象归属和未知结果保护随切片实现，不留到最后才补。

### MVP-04：补齐启停、页面与必要故障处理

| 子任务 | 产物与退出条件 |
|---|---|
| 04.1 | 原 Notebook 多次 Stop／Start，原 plan／charges／PVC 不变 |
| 04.2 | 条件更新与意图版本；旧 Start 最后到达时不能覆盖新 Stop |
| 04.3 | 创建未知、删除先到、进程恢复、同键冲突；形成明确的 blocked 原因与恢复说明 |
| 04.4 | 实例列表、详情、操作查询与最小 UI；复用 SG 输入输出和尺寸调整 |
| 04.5 | 专属 PVC 删除失败重试；清理未完成继续记录，不出现无人管理的卷 |

完整页面的仓库和路径在实际接入时登记；当前不编造前端落点。

### MVP-05：最终小规模验收

| 子任务 | 产物与退出条件 |
|---|---|
| 05.1 | 共享和整卡分别通过真实创建、GPU 程序、终端、启停与一次归还 |
| 05.2 | 保存文件、停止再启动、文件不变；最终删除后专属 PVC 按所选策略回收 |
| 05.3 | 原请求在镜像服务不可用时仍可重放；原 Namespace 不受配置变更影响 |
| 05.4 | 退额丢回执、Gov／Acc 短暂故障、Res 重启及租户 API／终端负例 |
| 05.5 | 更新操作手册、配置、已验证版本和未覆盖范围，完成受影响旧路径回归 |

MVP-01 后公共接线与 Res 的基础代码可并行，但 MVP-03 首次闭环需使用已对齐的真实公共合同。每个包允许拆小任务，不恢复旧版被裁剪的功能。
