# Block 运行时变更准备单

本模板由VM-00填成具体、可审的方案。**现在不构成执行授权。** VM-00R执行前必须补齐真实批准窗口与范围；空值不能用推测填充。

## 1 变更依据与范围

- 10～12目标当前只读确认的问题与证据（旧环境权限错误仅作线索）：
- 实际cluster ID/UID、执行host：
- 受影响节点、runtime及版本、真实服务名：
- 配置来源：原始配置/发行版生成输入；是否k3s/RKE2：
- 本次唯一目标：启用所需设备所有权处理并验证指定Block路径。
- 无关工作负载及禁止变更对象清单：

## 2 授权与空闲确认

- 用户确认“集群无人使用”的消息/记录引用：
- 明确授权本具体配置变更、节点、重启和探针的消息/记录引用：
- 维护窗口起止及沟通方式：
- 写入前只读检查结果；若发现仍有未批准中断的业务负载，暂停写入，不自行清空。

两项用户确认未齐时，状态保持BLOCKED_ENV，仅允许完善此准备单。

## 3 具体差异与恢复

- 每节点有效配置路径/生成来源：
- 原文件摘要、权限和备份位置：
- 已审最小diff（按实际runtime版本匹配正确配置段）：
- 配置语法/生成验证命令及期望：
- 节点执行顺序与每步继续条件：
- 对应服务重启命令（仅方案，执行待授权）：
- 失败停止条件：
- 已批准的恢复diff/恢复命令、节点恢复核验：

禁止把默认示例服务名/配置路径当现场事实；不改全局安全策略、镜像版本、其他runtime参数或shared gate。

## 4 验证对象与证据

- 获准namespace/UID、对象前缀与原生UID记录位置：
- import/clone/blank物料及不可变身份：
- 每候选节点配置生效验证：
- 新建或重建的CDI Pod范围：
- 非root块设备访问、最终PVC Block/RWO、VM读写观察：
- Node/基础组件恢复检查：
- 本次探针精确删除及存储回收清单：
- V01/V02实际结果、未通过原因：

成功只解除ENV-BLOCK的对应能力项，不代替后续产品链路验收。
